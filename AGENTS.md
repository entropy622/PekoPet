# PekoPet

Build the Windows x64 desktop companion with Rust/Tauri/React and a separate native Cubism D3D11 window. PekoPet owns its agent loop source (vendor/peko-agent-loop/src), runtime composition, process lifecycle, tools, approval policy, sessions, memory and reminders. Start scripts/start-agent.mjs directly as the application's Node backend. Never launch dsh CLI, load a desktop profile tree, create profiles/peko or require a separate dsh connection. Reuse pinned lower-level libraries and the MIT React components. Read only model/provider, MCP and skill configuration from DSH_HOME's desktop/home patch documents, resolving credentials through the shared managed store. Configuration edits write only the addressed shared item; other runtime settings and data belong under DSH_HOME/peko-pet. Legacy PekoPet migration copies owned roots and child sessions, referenced attachments and reminders without changing original session generations. Hand off only PekoPet-owned reminders by deactivating their legacy source records with a recovery receipt; preserve unrelated reminders. Start the owned scheduler after handoff. Publish the migration marker after the loop and history are ready; roll back uncommitted copies on startup failure.

Own code uses MIT. Preserve third-party licenses. Only SDK files named in its redistribution manifest may be committed. Model caches, credentials, session logs, local state and build products stay out of Git. Models from LLM_Live2D are local evaluation assets unless redistribution permission is documented.

The owner authorized a private reusable Live2DModels repository on 2026-11-11. Store personal model resources only in the optional models submodule, retaining original files and creator notices. Keep that repository private and do not grant others access or change its visibility. Public PekoPet commits contain only its gitlink and integration metadata; public CI initializes vendor/cubism-framework explicitly and never recursively fetches the private library. Portable directories and ZIPs exclude models. Publish private model commits before updating the consumer gitlink. Prior local imports and cached characters remain valid when the optional library is unavailable. Keep watermark, clothing and hardware/game-button controls outside the semantic avatar catalog. Render new characters with --check-avatar and --render-portrait offscreen, inspect the actual output, and keep generated images under ignored work or the local icon cache.

On 2026-11-09 the repository owner accepted the Live2D Proprietary and Open Software licenses and authorized official SDK downloads for PekoPet development, including this repository's CI. Core 5-r.5 lists the Windows library for redistribution, but omits its header. Keep that header under ignored local/cubism-core/include. Fork and pull-request checks must not accept a new license on behalf of another contributor.

Keep one JSON-RPC writer per process. Only root assistant text can emit avatar cues; tool output, reasoning, code and replay must not trigger motions. Approval defaults follow dsh. Never auto-grant an approval.

Expression cadence belongs in the avatar prompt. Derive examples from the active catalog and check real-model marker placement and duration; keep semantic choices with the model and do not add keyword-triggered emotion rules.

Run Node tests with `npm test`, Rust core tests with `cargo test -p peko-core`, and the native app build with `cargo build --release -p pekopet`. Inspect the rendered Web UI and native windows and real model before reporting visual completion. Record outstanding acceptance work in docs/ACCEPTANCE.md.

Use local incremental builds for UI iteration: `npm run build` compiles, and `npm run dev` compiles and launches. These commands load the installed x64 Build Tools environment. Keep GitHub Actions for integration and portable candidates; do not wait for cloud builds between local UI edits when the local toolchain is available.

Do not take over the foreground desktop for routine UI validation. Use `npm run check:ui` for the isolated offscreen Tauri/WebView2 app, CDP interactions and screenshots, then headless WebKit frontend checks. This mode uses a temporary DSH_HOME and a scripted model, creates no visible pet or tray, registers no pet hotkeys, never moves the system pointer, and never activates a window. It exercises the owned loop and real file tools only inside its temporary workspace. Generated Live2D portraits and icons stay in the local model cache with attribution. Keep explicit desktop-only acceptance items in docs/ACCEPTANCE.md. Keep ordinary WebView2 security features enabled during startup checks. Inline the pinned module-loader bootstrap through structured index injection before the shell executes; serve authenticated index routes with no-store and retain the revisioned application-bundle routes.

The whole application window is React. Keep the default surface a minimal companion conversation: no permanent workbench sidebar, project dashboard or model/permission toolbar. History and new conversation belong in the titlebar; companion settings and work options open on demand. Keep approvals, questions, errors and Stop visible when needed. Reuse the pinned dsh editor, messages, tools and session machinery; never maintain a second simplified chat renderer. PekoPet's titlebar, companion panes, model portrait, cue display projection and Soft UI tokens live in plugin/frontend. Pinned MIT sources live in vendor/dsh-ui-chat and vendor/dsh-ui-conversation; preserve upstream ownership and keep local changes documented in their SOURCES.md. Keep persisted session text intact. Only root assistant prose drives native avatar cues through the Rust parser. The first desktop target is Windows x64; Win32/D3D11 desktop-pet rendering remains Windows-specific.

Do not show dsh's product announcements, preview notice, official-brand chrome, product feedback or automatic DeepSeek sign-in onboarding. Use the public slot priority mechanism to complete the welcome-notice and deepseek-official onboarding steps without opening a modal or writing an acknowledgement. Do not redeclare their child slots. Keep provider configuration, model selection and actual provider names intact; identify dsh only as the shared configuration source. Retain third-party license notices in source and distribution.

Use a light Soft UI palette: mist canvas #f1f5f9, white surfaces, indigo #6366f1 actions, slate text, mint/rose/amber state accents. Buttons and inputs use 16px radii, cards 24px, tinted soft shadows and readable 14–16px body copy. Respect reduced-motion preferences. Default window is 720×760; keep every pane usable at 600×620 and retain keyboard, Chinese input, selection, copying and scrolling behavior from dsh.

Release publication is manual through Publish release. Build main with the reusable Windows workflow, derive the tag from matching package/Cargo/Tauri versions, and publish only after the portable asset uploads. Preserve published tags; resume only a draft belonging to the exact build commit. Keep SDK consent limited to entropy622/PekoPet.
